## A. 现在就能做（游客可见 · 本地能验 · 一轮 CI 可验收）

### A1. 板块页的「筛选 + 排序」——目前**一个都没接**（最值钱的一块）

> ✅ **Sprint 20 已完成**：分类（含「全部」，11 个/板块）+ 排序时间（热门 / 一天 / 两天 / 周 / 月 / 季）
> 已接成板块页顶部的筛选条，分类在最前。精华 / 投票 / 活动按用户决定**跳过**。
> 见 `docs/Sprint20-Changelog.md`。**A5 未表态、A2/A3 见下。**

从真实板块页（`forumdisplay.php?fid=14`，游客可见）解析出的原生入口，全部是站点现有能力：

| 类别 | 站点真实入口 | 证据 |
|---|---|---|
| **主题分类（11 个）** | `filter=type&typeid=10..19,44` | 心得技巧 / 绿色汉化 / 游戏 / 多媒体 / 数据库 / 实用工具 / ROM / 硬件报告 / HPC / 求助 / 站务 |
| **精华** | `filter=digest` | 标签 `精华` |
| **投票** | `filter=poll` | 标签 `投票`（**说明站点确实存在投票主题**，见 A4） |
| **活动** | `filter=activity` | 标签 `活动` |
| **热门** | `filter=&orderby=heats` | 标签 `热门` |
| **时间范围** | `orderby=lastpost&filter=<秒>` | 一天 / 两天 / 周 / 月 / 季（86400 / 172800 / 604800 / 2592000 / 7948800） |

**现状**：我们的板块流永远只显示「默认第一页」，上面这些入口**一个都没有**。
`PaginationParser` 只处理翻页，不认识 `filter=` / `orderby=`。
⇒ 用户没法只看精华、没法按分类筛、没法看最近一天的新帖。这是**功能缺口里最大的一块**。

**做法**：在板块页顶部（板块胶囊下方）加一条可横向滚动的筛选条；筛选状态并入请求参数；
解析器读懂 `filter` / `orderby` 的当前选中项（页面会高亮当前项，可据此还原状态）。
分类列表按板块不同，**运行时从板块页解析**，不硬编码。

**验证**：`analysis/fid14.html` 就是这个页面；`verifypc.mjs` 可以先跑通选择器再写 Swift。

### A2. 「全部板块」浏览入口 —— **页面已经是死代码**

- `Features/Forums/ForumListView.swift` + `ForumListViewModel.swift` **全仓库没有任何调用点**
  （已 grep 全仓：只有定义，没有 `ForumListView(`）。
- 而它依赖的 `ForumRepository.sections()`（`ForumMenuParser`）**是活的、并且工作正常** ——
  「我的 → 板块管理」用的就是它（`BoardManageView:157`）。

⇒ 已经写好一整个「全部板块」页面，却**没有入口**。补一个导航入口即可
（建议放首页板块条旁 / 板块管理页顶部），顺带能把远端板块一次性铺开供用户置顶。

### A3. 非图片附件的出口 —— 现在**只有一个小回形针**（✅ Sprint 20 已完成，见 `Sprint20-Changelog.md` §二）

- `hasAttachment` 目前唯一的用途是在列表行画一个 `paperclip` 图标。
- 详情页 `PostContent` 只渲染**图片**（`ThreadImageParser.parseContentImageURLs`），
  zip / pdf / txt 这类附件**在详情里根本不出现**，也就没有任何打开 / 分享的可能。
- 解析器其实已经会识别附件引用：`ThreadImageParser.isAttachmentReference` 认得
  `attachment.php?aid=` 与 `[attach]`。

**做法**：详情页楼层底部加「附件区」——列出文件名（`<a href="attachment.php?aid=N">名字</a>`
的可见文本）+ 大小，点按用系统「打开/分享」处理。**不做假下载**：拿不到 `aid` 就不显示。

### A4. 投票帖的正文渲染

A1 的「投票」筛选证明**站点确实有投票主题**（`filter=poll`）。这类帖子的正文是一个
`<table>` 投票框，我们现在把它当普通 HTML 走 `HTMLContentView`，很可能渲染成一段乱文本或空白。
**先做一次抽样**（`pcfetch.mjs` 抓 `forumdisplay.php?fid=14&filter=poll` 找几个 tid），
确认现状后再决定是「如实展示投票选项与票数」还是「明确标注不支持投票，给网页出口」。

### A5. 夜间模式的图片处理

参考实现 `webrules/4d4y` 有现成做法（`ColorInversionTransformation`，三通道取反 + 255 偏移），
解决**论坛图片普遍白底、夜间刺眼**。我们的深色模式是纯黑底，白底图会非常晃眼。
（参考实现里 `isPredominantlyWhite` 判断写了但没启用，实际是无条件反转 —— 我们可做得更细：
只对**以白底为主的图**反转，避免把本来就暗的图反成白的。）

## B. 必须真机登录才能落地 / 校准（需要你配合一次）

| # | 项目 | 为什么必须登录 |
|---|---|---|
| B1 | **发帖的主题分类 `typeid`** | 现在发帖**完全不带分类**，而站点主题都带 `[心得技巧]` 这类前缀（A1 里 11 个分类就是它的来源）。不发分类在开启「必须选分类」的板块会被拒。分类名可从板块页链接解析（游客可见），但**最终要以发帖表单的 `typeid` select 为准** |
| B2 | **附件上传两步协议真机验证** | `SWFUpload` 第一步要 `form#imgattachform` 的 `uid` / `hash`，而 **`post.php` 是登录门**，游客看不到。这条是全项目**最该先验**的（Sprint 18 才按参考实现重写） |
| B3 | `my.php` / `pm.php` / `space.php` / `search.php` 结构校准 | 四个页面游客全部不可达（HTTP 200 +「您还未登录」+ 登录表单）。现有解析器是「链接 / 正则 / 启发式」驱动，理论跨模板可用，但**「结构未识别」态只能靠真实 HTML 收敛** |
| B4 | **编辑 / 删除自己的帖子与回复** | `editpost.php?action=edit&tid=`，论坛客户端的基本功能，目前**完全没有**。凡是「解析表单再提交」的流程都必须在登录态下校准（而且要先确认拿到的不是登录门页面） |

**需要的配合**：在你手机上用浏览器登录后，把 `my.php` / `pm.php` / `space.php` / `search.php` /
发帖页（含 `#imgattachform` 与 `typeid` select）/ `editpost.php` 的页面**另存为 HTML 发给我**即可。
（不需要把账号密码给我；存下来的 HTML 里不含密码。）
