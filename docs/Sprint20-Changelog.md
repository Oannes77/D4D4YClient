## 一、板块筛选条：分类在前，排序时间在后

### 站点本来就有，我们一个都没接
从真实板块页（`forumdisplay.php?fid=14`，**游客可见**）解析出的原生入口：

| 组 | 站点真实链接 | 实测项 |
|---|---|---|
| **主题分类** | `filter=type&typeid=NN` | 心得技巧 / 绿色汉化 / 游戏 / 多媒体 / 数据库 / 实用工具 / ROM / 硬件报告 / HPC / 求助 / 站务（**每个板块不同**） |
| **排序 · 时间** | `orderby=lastpost&filter=<秒>` / `orderby=heats` | 一天 / 两天 / 周 / 月 / 季 / 热门 |

改动前，板块流**永远只显示默认第一页** —— 看不了分类、换不了排序。

### 做法：只搬链接，不拼参数
- `Parsers/BoardFilterParser.swift`（新）：分类取 `div.threadtype a[href*=filter=type]`；
  「全部」与排序取 `ul.itemfilter` 里的链接；顺带**主动跳过** `filter=digest|poll|activity`
  （用户判定精华 / 投票 / 活动没用）。
- `Models/BoardFilter.swift`（新）：`BoardFilterOption`（`title` / `path` / `isSelected`）
  与 `BoardFilterBar`（`categories` + `sorts`）。**`path` 是页面里那个链接的原样相对地址**
  （只剥 `sid`），客户端不拼 `filter=` / `orderby=` —— 站点改参数名也不会让我们失效。
- `Shared/BoardFilterBarView.swift`（新）：横向胶囊条，分类在前、竖线分隔、排序时间在后；
  选中项自动滚到视野中央。
- `HomeViewModel`：新增 `filterBar` 状态与 `applyFilter(_:)`；`loadFirstPage` 改为统一走
  `load(path:)`。**下拉刷新刷新的是「当前视图」**（`currentPath`），不会再一刷就把筛选刷掉。
- **翻页天然带筛选**：`PaginationParser` 取的是页面里的下一页链接，而那个链接本身就带
  `filter=type&typeid=10&page=2` —— 不需要我们做任何事。

### 选中态以页面为准
不在客户端记账「当前选中谁」：点一下 → 请求那个链接 → **由返回的页面**告诉我们谁被选中
（`li.current` / `<strong>`）。所以切板块、切分类、下拉刷新之后状态永远不会错位。

## 二、文件型附件出口

### 之前只有一个小回形针
`hasAttachment` 唯一用途是在列表行画个 `paperclip`；zip / rar / pdf 这类附件
在详情页**根本不出现**，也就谈不上打开或分享。

### 现在
- `Parsers/AttachmentParser.swift`（新）：解析 `div.postattachlist dl.t_attachlist`，
  **排除带 `attachimg` class 的图片附件**（它们已由正文图片网格渲染，否则同一张图会出现两遍）。
  取文件名（锚文本）、体积（`(309.58 KB)`）、下载次数（`下载次数:8115`）。
- `Post.attachments`（新字段，默认空数组 —— 老调用点无需改动）。
- `PostContent`：楼层底部「附件 N 个 · 下载需论坛登录」+ 每行 `图标 + 文件名 + 体积·下载次数 + 分享`。

### 为什么只做「分享」不做「下载」
iOS 上没有统一的「下载到哪」；系统分享面板本身就含**存储到文件 / 用浏览器打开 / 拷贝链接**
三条真实出路。**不做一个假的下载进度条**。
另外实测：游客直接访问 `attachment.php?aid=` 返回的是
「附件文件不存在或无法读入」的 HTML 页 —— 所以界面上如实写明「下载需论坛登录」。

⚠️ 附件地址**原样保留签名 token**（那是站点自己的凭据地址，不能改写），只剥 `sid`
（属于本次会话，分享给别人没用且会外泄会话 ID）。

## 四、🔴 差点又白挂一轮 CI：顶层类型重名

`PostAttachment` 这个名字**项目里已经有了**（`Repositories/PostRepository.swift`：
上传载荷 `fileName/mimeType/data`）。我新加的详情页附件模型也叫 `PostAttachment`
⇒ **`invalid redeclaration`，必然编译失败**。

三个工具各有一半责任，都已补齐：

1. **`dups.mjs` 老用法是「把想检查的符号名当参数传」** —— 我这次没传参数，它就什么都不查、
   安静通过。**「只检查我记得的名字」等于不检查**。已改为**默认全量扫描**。
2. **`swiftlint-lite` 其实报了警告**（`PostAttachment(…) 未提供必填参数：fileName, mimeType, data`），
   一开始被我当成误报 —— 回头看那正是**重名的现场证据**（它把两个同名类型的属性混在了一起）。
3. `dups` 的「文件作用域」判据改成**声明顶格**（本仓库顶层声明一律顶格、嵌套一律缩进），
   比手写花括号配对稳（配对会被注释/字符串里的花括号带偏），且不再误报嵌套的 `enum Outcome`。

最终把新类型改名为 **`PostFileAttachment`**（与上传载荷语义区分开）。
`dups` 现在输出「✓ 顶层符号无重名（扫描 168 个文件作用域符号）」。

### 附件区为什么没入镜（已查明，不是功能没生效）
用真实夹具**逐层**核对过：本批两个演示帖的文件型附件都在**靠后的楼层** ——

| 帖子 | 文件型附件所在楼层 |
|---|---|
| 439576（`threadImages`） | 第 **3** 楼（2 个）、第 **9** 楼（1 个） |
| 193033（`thread`） | 第 **11** 楼、第 **13** 楼 |

而截图只滚到**首帖**的操作栏 ⇒ 附件行根本不在画面里。
（反过来也说明解析是对的：首帖楼层没有文件附件，所以那里不该出现附件区 —— 界面上确实没有。）

### 因此补了三处（本轮追加）
1. 附件行加 `accessibilityIdentifier("post-attachment")`，让截图脚本能「滚到附件那一行」。
2. 新增截图目标 **`threadAttachments`**（滚到 `post-attachment`）⇒ 清单 10 界面 20 张 → **11 界面 22 张**。
3. **`scrollIntoView` 上限 6 → 15 次**。原因见本批的浅色 `threadImages`：**停在图片顶上根本没滚动**
   （深色那张滚到了操作栏）。详情页改成「图片一张一行」后首帖本身就一屏多高，6 次常常够不到；
   上限提高不影响正常情况（命中即停）。这类「等到了锚点但验收点没入镜」的老毛病，
   根因就是滑动预算不足。

## 七、修订（用户澄清「标签」的含义）

用户原话：
> 「你没有明白我说的标签的意思，**标签不用在首页显示，而是在发帖的时候，增加对应标签的下拉选项**。
> 首页现在这个发帖有点太碍眼，毕竟 threads 是快速发帖不用标题。所以发帖这个按钮可以和搜索做成一排，
> 下来的时候前面是搜索，后面是发帖按钮。类似这样的界面（🔍 　 ）搜索[发帖]」

### 7.1 主题分类：从首页挪到发帖页
我把「标签」理解成了首页的分类筛选条，**错了**。分类的真实身份是**发帖时贴给主题的标签**
（列表里显示成 `[心得技巧]` 前缀），所以：

- **首页排序条只剩排序与时间**（热门 / 一天 / 两天 / 周 / 月 / 季），分类整组移除；
  `BoardFilterBar` 不再有 `categories` 字段。
- 新增 `BoardCategory(id:name:)` 与 `BoardFilterParser.categories(document:)`：
  从**该板块页自身的分类链接**解析 `typeid` 与分类名（游客可见，不需要登录）。
- `ForumRepository.categories(fid:)`：发帖页按当前板块拉一次。
- **发帖页**「发布到」下方新增「分类」下拉；该板块没开分类就整块不显示（不摆空下拉）；
  换板块会重新解析并**清空已选**（避免提交一个张冠李戴的 `typeid`）。
- 提交时带 `typeid`（字段名与做法取自参考实现 `docs/RefProject.md` §4；用户没选就不覆盖页面自带值）。

### 7.2 首页顶部：搜索 + 发帖合并成一排，且**整排默认收起**
用户选了「默认什么都不显示」这一版：

```
[🔍 搜索 Discovery            ]  [发帖]      ← 下拉回弹才出现
```

- `CollapsibleSearch` 增加 `onCompose`：展开时右侧出现一个「发帖」按钮（紫色圆角）。
- **删掉**原来的整行「发新帖…」入口（`Shared/ComposeEntryBar.swift` 一并删除，不留死代码）。
- 于是：平时首页顶部只有「板块胶囊 + 排序条」，看不到搜索也看不到发帖；
  **发帖与搜索同一可见性 —— 想发帖先下拉**（已与用户确认）。
- 连带效果：上轮那个「发帖入口太碍眼」的问题彻底消失（它现在根本不占常驻空间）。

### 7.3 截图机制补一个能力：`pullDown`
「默认收起、下拉才出现」的界面，不先下拉截图永远是空的 ⇒ 给 `Target` 加了 `pullDown`：
截图前 `app.swipeDown()` 一次。新增目标 **`homeSearchCompose`**（下拉态）⇒
清单 **12 界面 = 24 张**。

### 7.4 镜像验证同步
`analysis/verify20.mjs` 改成：排序条只断言 sorts；**另加 `categoriesForComposer` 的断言**
（fid=14 → 11 个分类，心得技巧#10 / HPC#44，且不得含「全部」）。全部通过。
`swiftcheck` / `swiftlint-lite` / `dups` 三项亦全过。
